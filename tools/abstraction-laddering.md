# Abstraction Laddering

Also: Why-How Laddering (Stanford d.school). A problem-framing ladder that the LUMA Institute published under this name in 2012. It most likely comes from the Creative Problem Solving ladder of Sidney Parnes (1967) and from Min Basadur's challenge mapping. Use it to state a problem at a broader or narrower level before you solve it. It is not Hayakawa's ladder of abstraction for language.

## Structure

```
broader statement    ("Why else?" adds more)
   ^  "Why?" or "Why is this important?"
start statement
   v  "How?" or "What's stopping you?"
narrower statement   ("How else?" adds more)
```

"Why?" asks for the purpose, not for the cause.

## Steps

1. Write the problem as one short statement. Start it with "How might we ...?"
2. Ask "Why?". Write the answer above it as a new statement in the same form
3. Ask "Why else?". Write each answer beside the first
4. Repeat steps 2 and 3 on the new statements. Stop when a statement is meaningful but you cannot act on it
5. Go back to the start statement. Ask "How?" and "How else?". Write the answers below it. Repeat down to a concrete action
6. Choose the level to work on: a statement that is meaningful and that you can act on. Make it the new problem statement

## Checks

- Stuck at the top: a broad statement feels like insight but gives no action. Go down with "How?"
- Ladder not used: the work continues on the start statement. Name the chosen level and work there
- One chain only: one "Why?" chain gives one new frame. Ask "Why else?" and "How else?" at each level
- Vague top: an abstract phrase means something different to each reader. Write concrete words

## Wrong Tool When

- You must map the functions of a design: use a FAST diagram (value engineering)
- You must find the values behind a customer's choice: use the laddering interview (consumer research)
