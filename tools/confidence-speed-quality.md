# Confidence Determines Speed vs. Quality

A product-building rule from Brandon Chu (2018), the sixth of his product management mental models. Your confidence decides how you trade speed against quality in a piece of product work.

## Structure

Two confidence questions, each answered with evidence:

| Question | Low confidence | High confidence |
|---|---|---|
| Is the problem important? | Customers have not confirmed it | Customers confirmed it |
| Is the solution correct? | The solution is your idea and is not tested | You know what to build, and customers validated it |

Chu describes a line with two ends. Wes O'Haire (2019) adds the middle case:

| Problem confidence | Solution confidence | Favour |
|---|---|---|
| Low | Any | Speed |
| High | Low | Speed and quality in balance |
| High | High | Quality |

```
low confidence  <---------------------------------->  high confidence
ship fast, get validation from customers              no shortcuts, build it to last
```

## Steps

1. For each piece of work, answer the two questions. Write the evidence next to each answer
2. Problem confidence low: favour speed. Do the least work that shows if the problem is real. Chu's example is a landing page for a feature that does not exist yet
3. Problem confidence high, solution confidence low: balance the two. Build a small version that can show if the solution works, and say that it is a test
4. Two times high: favour quality. Customers will need the feature for a long time, so take no shortcuts
5. Rate the work again when new evidence arrives

## Checks

- Confidence means validation by customers, not conviction. "We are certain" with no evidence from customers is low confidence
- The rule tells you how to build each item. It does not rank the items
- Agree the mode with the stakeholders. A fast test that others take for the finished product causes conflict
- A request for a solution ("build an API") is evidence for a problem, not for that solution

## Wrong Tool When

- Safety-critical or regulated work: quality is fixed and is not traded
- The question is which item to do first: use an impact-effort matrix or a decision matrix
